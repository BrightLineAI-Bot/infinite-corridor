# Hammerfall stomp — owner intake and architecture

Recorded 2026-11-08. Isolated candidate: `claude/close-view-hammerfall-stomp`, initial tool base `48a23cc7`. This is a source audit and proposed implementation contract, not implemented or published animation. The coordinator will merge the reviewed primary/common-clock foundation before implementation. ## Exact requested pose

One leg lifts. Both fists are **clenched and crossed together in front of the chest**. The lifted foot then **stomps down into a wide stance with a slight knee bend**. Both arms **uncross and drop beside the body, with elbows still bent**; the fists must not extend all the way to the ground. Hammerfall lands with the stomp. No giant held hammer is required. Actual Corridor Golem mode/companion mechanics remain independent.

Only an actual accepted Hammerfall use starts the pose. Refusals animate nothing; equipping a tool does not transform the body. Preserve movement, collision, effect targeting, damage, costs, cooldowns, Echo copies and special-form precedence unless the coordinator explicitly approves a mechanical change. The owner authorized regression tests for this scope. Approved imported geometry (3170 triangles), proportions (.80 width/.82 depth/.62 hands), head, mask, amber eyes, neck bridge, textures and source archives remain fixed. No new asset, dependency, render pass, program, draw or buffer type.

## Timing and effect facts

`BRAWLER.hammerfall` already defines **.32 s delay, .25 s effect lifetime, 1.2 s cooldown, 2.6 reach, 1.5 radius and .6 stun**. Spellblade/Shadow Boxing can modify the existing target/reach contract. `brawlerTool` locks the target/ahead effect center on acceptance. This is a ranged ground strike: the center is not the player's foot. The existing target telegraph/falling conjured hammer and shock ring are separate from the held model.

`updateEffects` subtracts `dt` and continues while delay is positive, then pulses on the following update. Read-only actual Game probes found first damage **333.33 ms after an input accepted inside Game.update at both 30 and 60 fps**. A direct fireSecondary acceptance followed by updates hit at **366.67 ms (30 fps)** or **350 ms (60 fps)**. Both dealt 98 damage in the same controlled fixture. These are measured discrete-step results, not a replacement balance constant. The current 240 ms body presentation ends before any of these impacts.

Effects, delay, lifetime and hit records survive an in-place area snapshot/reload. Pause prevents effect advancement. Ordinary casts/jumps cancel the old accepted body record through the common cancellation API, but do not remove an already-created Hammerfall effect. Tool Echo copies have their existing additional .22 s gaps and must not replay this body stomp. Corridor Golem still starts from the original target and `now + B.delay * 1000`, with its own rise, punches, cooldown and area lifetime.

**Recommended option: presentation only.** No new mechanical startup is needed. Extend this accepted presentation to the existing **320 ms preparation + 250 ms effect/recovery**, using the common accepted-action clock and a link to the original non-Echo effect. Keep canonical `attackUntil = now + 240` and every effect/damage clock untouched. Merely mapping a 570 ms wall-clock animation to nominal 320 ms is insufficient for direct producers, uneven frames and exact resume; the visible plant must consult the existing effect's first-pulse state.

A bounded implementation can add normalized accepted `hammerEffectId`, `hammerDelayMs` and `hammerRecoveryMs` metadata. Capture the original effect returned by `fx(...)`, before Echo copies are appended. Pure presentation timing resolves that exact non-Echo effect: while `delay > 0`, preparation elapsed is accepted delay minus remaining delay; while delay has expired but `pulseIndex === 0`, hold just above the plant; once `pulseIndex > 0`, contact/recovery elapsed derives from accepted effect lifetime minus remaining `life`. No new hit or event is emitted. Missing/cleared linked effects end this new presentation; legacy hammer records without a link retain their old fallback.

Use one resolver for Close View, cancellation and export, with optional effect/now context on the common clock helper; do not add a competing hammer timer. The resolved deadline can be `now + durationMs - resolvedElapsedMs`. Initial `actionVisualUntil` and saved `actionVisualMotion` remain the common accepted fields; exact remaining presentation is exported from the same resolver. Constructor validation still uses the saved remaining amount, then normal effect restoration supplies exact timing. Cancellation remains authoritative even while the linked effect continues. This contextual resolver is a proposed bounded extension for coordinator approval before implementation, not an implemented API.

**Alternatives:** nominal 320 ms contact without effect linkage is simpler but can lead the actual hit by a frame and fails the strict timing requirement under uneven updates. Moving the area of damage under the foot, changing the .32 delay, cancelling already-created damage on interruption, or stopping movement would be deliberate mechanical changes; none is required for the recommended visual pass or approved by this document.

## Derived pose and rig contract

No source clip is a stomp. Reusing the complete dagger, roll or Punch clip would introduce the wrong motion. Label the result `derived-hammerfall-stomp`. Reuse only the existing analytic limb alignment/quaternion machinery and each hand's own source Punch finger closure.

Source +Z is forward, +Y is up. Real legs are left UpperLeg30 → LowerLeg29 and right UpperLeg32 → LowerLeg31. Feet1/36 are children of Root38, not the shins. Derive each virtual ankle from the fitted inverse binds: transform the fitted Foot joint origin into the corresponding LowerLeg frame. Measured vectors are approximately `(±.00106048, .5869867, -.00981581)`; derive them from data rather than embedding those numbers.

Solve hip–knee–virtual ankle as a fixed-length two-bone chain with a forward knee pole (source +Z, projected perpendicular to the hip-to-ankle line). Use law-of-cosines elbow/knee construction and parent-frame quaternion alignment, then rebuild FK. Drive each independent Foot node from the solved ankle through inverse Root38, subtracting `fit.offsets` when writing pose translation. Match orientation through the same parent transform. Do not stretch scales or move only the foot track. Shoelaces follow their actual parent feet.

The existing source is not mathematically zero-gap at every gait sample: the fitted-bind virtual-ankle residual measured over 25 samples is .00813 source units for Idle, .01884 for Walk and .05206 for Run. At height1.3776, world scale is approximately .591. Preserve the current base-pose residual at blend weight zero and fade it out as the derived layer takes over: after blending leg rotations and rebuilding FK, place the foot at the final virtual ankle plus `(1-weight) * baseAnkleResidual`. This gives exact entry and connected full-weight legs instead of snapping an approved gait to a different bind pose. Both foot orientation and translation blend; floor clearance uses the actual deformed foot vertices.

Keep the source Root/game position untouched. A small visual Body33 lowering during contact supplies knee flexion, with both legs solved against their planted targets. All gameplay elevation/lift applies once through the existing final transform. The support foot stays grounded during the lift. A proposed calibration range is lifted sole .18–.25 world tile above its ready sole, planted foot spacing 1.4–1.7 times ready spacing, and pelvis lowering .035–.06 tile. These are bounded art targets to validate, not measured final geometry. While movement continues, the pose follows the actor; this pass does not promise world-locked feet under a moving root or add movement inhibition.

For arms use shoulder→elbow→wrist chains12/11/7 and22/21/18. Preserve sibling thumb roots9/20 when orienting the palms. Copy closed-finger rotations from each side's own Punch channels6/5/9/8 and17/14/20/19; never copy mirrored local quaternions or shrink hands again. Two wrist/grip targets cross the centerline in front of the chest, with a small separate height/depth plane to avoid interpenetrating forearms. During contact, move targets out beside the hips, roughly .65 arm-reach below the shoulder and slightly forward. Keep shoulder-to-wrist distance below .85 total arm reach; elbow interior angle should remain about 75–130 degrees at the planted pose, never nearly straight. Numerical positions need actual FK and CPU-sheet calibration before acceptance.

Proposed choreography within the effect timeline: 0–160 ms lift/cross; 160–240 ms clear raised/crossed silhouette; 240 ms–first pulse fast foot descent and arms uncross/drop; first pulse through roughly80 ms of effect age grounded wide stance; remaining effect lifetime returns smoothly to normal carry. The last pre-pulse sample retains visible sole clearance; the pulse sample is planted. At both endpoints return the exact nonzero-idle/partial-walk baseline. Keep ordinary primary carry as the body base while the held-gear selection is empty for the stomp; these are distinct inputs. Capture accepted logical pose/gait/yaw using the existing presentation-cache pattern where required. Test actual production entry from Pike and low Cleaver carry, not only a bare idle sampler.
