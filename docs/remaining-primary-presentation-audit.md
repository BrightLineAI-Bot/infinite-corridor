## Canonical inventory

The authoritative runtime table contains four primary profiles: Iron Fists, Salvage Blade, Cinder Pike, and Verge Cleaver (`src/items.ts:11`). Generated ordinary primaries add only Pike and Cleaver (`src/items.ts:3`). `primaryProfile` recognizes those profiles by canonical ID/name and deliberately sends every missing, legacy, or future unknown primary identity through the Salvage profile (`src/items.ts:50`). The schema-14 fresh save carries Salvage Blade (`src/types.ts:14`). There is therefore one remaining presentation family after the published Pike/Cleaver and Iron Fists work: Salvage plus its unknown-primary fallback.

Accepted ordinary melee records normalize that family to `salvage-blade` and retain the real aim and 240 ms action clock (`src/game.ts:6191-6219`). Salvage deliberately does not advance Pike/Cleaver's optional staged `primaryStep` counter. Close View uses accepted identity through recovery and equipment changes, while idle resolves the currently equipped unknown primary to the same family (`src/close-view.ts:1929-1931,2096-2100`). The imported Wayfarer attaches the existing blade recipe to its final right-hand socket (`src/close-view-models.ts:261-284`) and uses the generic source dagger attack (`src/close-view-hero.ts:291-316`). The normal Wayfarer uses the existing native model while that asset is unavailable, and native special forms retain their own authored bodies; both use the existing generic melee curve, including early contact and bounded recovery (`src/close-view-models.ts:307-319`). This fallback is intentionally one generic animation family; stage 2c does not invent three distinct Salvage motions.

Action precedence remains shared rather than weapon-specific. The renderer selects stun, stagger, hit, semantic action, accepted attack, fist charge, cast, windup, jump, then locomotion (`src/close-view.ts:2048,2077`); the imported action layer selects knockdown, dodge, hit, accepted attack, charge, cast, then jump (`src/close-view.ts:2136-2151`). Strike and delayed-Echo origins remain gameplay geometry from `meleeAttackGeometry`, `meleeStrike`, and the recomputed accepted profile, never the visual mesh or hand socket (`src/game.ts:6202-6227,3400-3404`).

## Regression receipt

It checks idle carry, accepted phase-zero continuity, contact, recovery, matching idle endpoint, accepted gear identity after switching, pause/schema-14 reload, unknown metadata preservation, refused/successful cast priority, and the longstanding mechanical delayed Echo's fresh canonical Salvage strike geometry. It deliberately does not depend on or assert the later raised Echo visual cue, fabricate Pike/Cleaver-only staged metadata, or require distinct three-stage Salvage motion.

The first regression run exposed a real imported-path boundary defect: generic accepted melee reset its imported idle base to clip time zero at phase zero, causing a measured maximum local jump of about `.058` tile. The bounded runtime correction treats only finite-`poseMs` generic `melee` as a timed imported action and forwards that accepted clock; legacy no-`poseMs` melee and unknown action profiles retain their previous neutral clock path. The native endpoint assertion measures continuity across `239.9 → 240 ms` rather than equating unrelated render histories; its `.003` bound covers the existing native model/turn float history and the observed result remains below it. No combat, save, stage, origin, or balance rule changed.
